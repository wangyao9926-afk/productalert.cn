# 目录采集质量验收

## 适用范围

本流程只用于用户已配置、公开可访问的品牌官网。不得使用代理、伪造身份、绕过验证码或规避站点访问限制。

## 首轮基线验收记录

每次首轮扫描都要记录以下内容：

- 站点与扫描任务 ID；
- 发现的商品候选数量（`discovered_product_count`）；
- 已验证入库数量（`stored_product_count`）和产品库实际数量；
- 受限流、被拦截、读取失败、解析失败和待重试的数量；
- `baseline_state` 与任务最终状态；
- 如公开平台目录端点可访问，记录其公开商品数量，作为覆盖率对照；如不可访问，明确标注“覆盖受限”。

## 判定规则

- 只有已验证入库商品大于零，且没有待验证、限流、拦截或读取失败候选时，才可标记为完整基线。
- 收到 HTTP 429 时，验收通过的前提是任务显示为 `partial_success` / `incomplete`，并在扫描页提供“继续扫描”操作。
- 出现待验证候选时，产品库数量只能称为“已验证商品”，不能表述为官网完整商品总数。
- 若公开目录端点返回完整商品数据，已验证数量应与该数量对照；存在差异必须记录差异和原因。

## 复验步骤

1. 在本地开发环境启动 API 与队列工作者，使用已有站点创建或继续扫描。
2. 查看 `GET /api/scan-jobs/{job_id}` 中的 `result.progress.quality`。
3. 在产品库按 `site_id` 筛选，核对数量、商品图片、卖点、价格及官网链接。
4. 把任务结果、错误分类和覆盖率结论附到测试记录中；不得把限流站点的局部结果标记为“全量完成”。
