# 抓取质量基础：第一阶段实施计划

## 目标

将当前的“发现变化”原型提升为可复核的监控闭环：一次抓取必须留下可追溯证据，接口数据契约必须稳定，并以回归测试锁住关键行为。

## 第一阶段范围

1. 修复 SQLite 到 API 的布尔值序列化契约。
2. 为页面快照保存最终 URL、抓取方式、HTTP 状态、内容类型与响应体大小。
3. 在静态内容不足时使用已存在的浏览器渲染作为回退，并把回退方式写入证据。
4. 为证据字段和 API 契约添加不依赖外网的回归测试。

## 明确不在本阶段处理

- 代理池、绕过验证码、登录态抓取或规避站点访问限制。
- 分布式调度、对象存储截图和视觉差异比对。
- 平台专用适配器、商品变体级跟踪和人工反馈学习。

## 验收标准

- `enabled` 在 API 中始终是 JSON 布尔值。
- 每条新的 `source_snapshots` 记录都包含抓取证据；旧数据保持可读取。
- HTTP 页面记录状态、内容类型和最终 URL；浏览器回退记录 `browser_render`。
- 单测、API 冒烟和通知/隔离冒烟全部通过。
