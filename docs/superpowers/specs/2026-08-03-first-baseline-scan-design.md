# 首次全站基线扫描与商品库设计

## 目标

用户输入一个品牌官网根域名并开始监测后，系统必须自动建立可验证的全站商品基线。基线完成前，用户可看到任务进度；完成后，用户可看到商品总数、每个商品的关键字段和官网链接。后续扫描只报告相对基线的重要变化。

## 用户流程

1. 用户在“新建监控”中输入官网根域名并保存。
2. 前端创建站点和监控源后，立即提交首次站点扫描任务。
3. 前端跳转到“首次扫描”状态页，并每 2 秒读取该任务状态。
4. 系统发现 Sitemap、集合页和产品页，去重后逐项提取商品。
5. 状态页持续显示：任务状态、候选商品数、已解析商品数、成功数、失败数、最近错误。
6. 任务成功完成后，显示“已建立基线：发现 N 个商品”，并提供“查看商品库”和“查看扫描证据”。
7. 商品库显示图片、标题、类型、卖点摘要、价格、划线价、币种、库存、变体数、发现时间和官网商品链接。
8. 后续任务使用已保存商品身份与字段快照，生成新品、价格、库存、变体和内容变化事件，而不是把基线商品当作新品通知。

## 架构与职责

### 前端

- `CreateMonitorPage`：保存成功后自动提交首次扫描，并跳转至扫描状态页。
- 新增基线扫描状态页：轮询单个扫描任务，展示实时计数、状态和失败原因。
- `ProductsPage`：按站点展示基线商品数量与商品列表；每个商品官网链接在新标签页打开。
- `MonitorsPage`：显示“基线建立中 / 已建立 / 失败”，提供“重新扫描”入口。

### 后端 API

- 复用 `POST /api/sites/{site_id}/scan` 创建任务。
- 扩展 `GET /api/scan-jobs`，允许按任务 ID 获取当前任务及其 `candidates_count`、`new_count`、`error_count`、状态、时间与信息。
- 扩展任务结果，以 `discovered_count`、`processed_count`、`failed_count` 和 `baseline_completed` 表示进度及最终结论。
- `GET /api/products?site_id=` 返回站点商品总数与上述商品字段；现有商品详情和证据接口继续作为深层入口。

### 后台执行

- Railway 使用 PostgreSQL 持久化站点、商品、快照、事件与扫描任务。
- Railway Redis/RQ Worker 异步消费站点扫描任务；Web API 不在请求线程内执行全站抓取。
- 发现顺序：`sitemap.xml`、站内商品集合/分页、已知产品链接；所有链接规范化并去重。
- 每个商品保留最终 URL、HTTP 状态、抓取方法、原始哈希、结构化字段、错误原因和截图证据。

## 数据与判定规则

- 首轮扫描中的有效商品写入 `products`，但不向用户发“新品”通知。
- 当首轮扫描完成且至少有一个有效商品时，标记来源的商品基线完成。
- 基线后首次出现的稳定商品身份（canonical URL、产品 ID、SKU、GTIN 或变体 ID）才生成新品事件。
- 价格、库存、变体、标题、描述/卖点和产品类型按字段比较；导航、Cookie 横幅、时间戳和推荐位不产生事件。
- 单个页面失败不终止全站任务；任务标记为 `success`、`partial_success` 或 `failed`，并给出可读失败分类。

## 错误处理

- 无法发现商品链接：完成任务但标记为 `partial_success`，提示用户添加集合页或 Sitemap URL。
- 403、超时、渲染失败、解析字段缺失：在任务与证据页显示分类和受影响数量。
- 队列或 Worker 不可用：前端明确显示“扫描服务未就绪”，不把任务误显示为完成。
- 页面产品数异常下降：标记为解析质量告警，不自动将历史商品批量删除。

## 验收标准

- 用户保存官网根域名后，5 秒内看到一个可追踪的首次扫描任务。
- 扫描期间可见已发现、已处理、成功和失败数量；任务完成后可见全站商品总数。
- 商品库中每条记录均可打开对应官网 URL，并至少包含标题、价格、币种、库存、类型和卖点摘要中的可用字段。
- 首次基线不产生新品通知；新增商品、价格或库存变化在后续扫描中产生可回溯事件。
- 10 个真实独立站样本中，任务失败必须有分类原因；解析质量异常不能静默覆盖历史数据。

## 测试策略

- 后端单元测试：基线扫描不生成新品事件；进度计数、部分失败和质量告警正确写入。
- API 测试：首次扫描创建后可读取单任务状态；站点商品列表含总数和关键字段。
- 前端合约测试：创建监控后自动发起扫描、显示进度、成功后进入商品库。
- 端到端冒烟测试：以固定许可测试页面建立基线并验证商品链接、结果计数和证据入口。
